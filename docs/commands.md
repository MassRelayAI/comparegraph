# CLI reference

Every command, with the flags that matter.

Global options on every command, before or after the verb: `--root <ROOT>` (the workspace, default `.`), `--pretty`, `--allow-unverified` (use an
external provider with no manifest), `--root-map FROM=TO` (repeatable: re-root the clone paths a store copied from another machine holds; `doctor` lists the
registered clones missing here under `unmapped_roots`). `comparegraph <verb> --help` prints every flag.

## Build and inspect

| Command | What it does | Flags that matter |
|---|---|---|
| `add <PATH>` | Register a clone. Read, never run. With `--replace` (and `--name <existing>`) it re-points that registered repo at `<PATH>` instead: claims and runs stay, the root flag is kept unless `--as-root` is passed too. It refuses an unknown name ("nothing to replace; drop --replace") and a path the repo already has. The envelope reports `old_path`, `new_path` and the new path's `head`, with a limitation saying the last build read the old path and to run `build` again. Licence and lane come from the clone's LICENSE file; a partial export has none, so `--licence <SPDX>` records one (the lane follows it), `--licence-from <SOURCE_CLONE>` reads it from the full source clone (refused if that clone has no recognised licence either), and `--lane take\|study` sets the lane outright (it wins over the licence's lane; any other value is refused). Explicit flags win over detection; with `--replace` they are applied to the row, and without them the row keeps its licence and lane. Repo notes: `--source-commit <SHA>` records the upstream commit an export was taken from (7 to 64 hex digits; a fresh `git init` of an export has `head: null`), shown next to `head` by `add`, `repos`, `build`, `show` and the vault; `--moved-to <REPO_OR_URL>` notes where the project's core now lives (shown by `repos` and `show`; a note, never followed); `--include <GLOB>` / `--exclude <GLOB>` (repeatable, gitignore-style: a name glob matches at any depth, `dir/**` everything under `dir`, a glob that matches a directory covers its files, an exclude wins over an include; a glob starting with `!` is refused) set the default subset `build` reads. Without a path, `add --name <existing>` with any of these (or `--licence/--lane`) amends a registered repo; `''` clears a note or a glob list. `--replace` keeps the notes except `source_commit`, which named the old checkout: it is cleared (limitation `source_commit_cleared`) unless given again. | `--name`, `--as-root`, `--replace`, `--licence`, `--licence-from`, `--lane`, `--source-commit`, `--moved-to`, `--include`, `--exclude` |
| `build <REPO>` | Parse a clone into the graph (one run). The envelope's `data` names the clone `path` it read and the `head` (short commit) it found there; `--progress` prints the same as its first stderr line. | `--provider` (default `reference`), `--providers a,b` (several engines in turn, with an agreement table), `--max-file-bytes`, `--max-files`, `--full`, `--progress` (stderr lines every 500 files and per pass; also `COMPAREGRAPH_PROGRESS=1`; stdout stays one envelope), `--include <GLOB>` / `--exclude <GLOB>` (repeatable; the file subset this run reads, replacing the repo's `add` subset when either is given; recorded on the run and returned as `data.include/exclude` with `data.source_commit`; a run read with other globs is never reused; files left out are counted in limitation `out_of_subset`; an external provider walks the clone itself, so its nodes outside the subset are dropped after it answers, limitation `subset_filtered`) |
| `check` | Verify schema, determinism and citation locations. Also counts `unbuilt_claim_runs`: claims whose cited run has no row or is not a finished build; each affected repo adds a problem line (`<repo>: <n> claims cite run <id> which was never built`) and the verb exits non-zero, like any other problem. `stale_locations` counts only locations of live claims (the latest claim per repo and feature, the one `matrix` and `export` treat as current) and each is a problem; `stale_locations_superseded` counts the stale locations of superseded claims (append-only history that cannot change) and is reported in `notes`, never as a problem. | |
| `repos` | Registered repos with their latest run: `head`, `source_commit`, `moved_to`, the default `include`/`exclude`, and the `include`/`exclude` the latest run read. | `--limit` (50), `--cursor` |
| `doctor` | Report the store, every provider and each agent client's registration. | `--bin`, `--brief` (plain text for a session-start hook: nothing without a store, else one or two lines; the one output that is not an envelope) |
| `conform <PROVIDER>` | Run the golden fixtures against a provider. | `--fixtures` |
| `catalog` | Print the MCP tool catalog as JSON. | `--check` (compare with `docs/catalog.json`) |

## Graph queries

| Command | What it does | Flags that matter |
|---|---|---|
| `search <QUERY>` | Full-text search over symbols of each latest run. | `--repo`, `--kind`, `--limit`, `--cursor` |
| `show <REPO> <QN>` | A symbol with callers, callees, community, licence lane, and the repo's `source_commit`/`moved_to` when set. | `--detail full` |
| `communities <REPO>` | Module clusters of the latest run. | `--limit`, `--cursor` |
| `traverse <REPO> <QN>` | Nodes reachable over calls, extends, implements, with hop distance and path. | `--direction`, `--depth` (3), `--max-nodes` (200), `--kinds`, `--min-confidence` (0.5), `--limit` (50), `--cursor` |
| `impact <REPO> [QN]` | Everything that transitively depends on a symbol or files, plus the tests that reach it. Summary first (`total`, `by_hop`, `by_kind`, `tests_total`), then `items` paged, best `path_confidence` first; the `tests` list is capped at `--limit` too, with a `tests_capped` limitation when cut (`tests-for` has the full list). | `--file`, `--depth` (5), `--max-nodes` (500), `--limit` (50), `--cursor` |
| `tests-for <REPO> <QN>` | Tests linked directly or through at most 3 call hops. | `--max-nodes`, `--min-confidence`, `--limit` (50), `--cursor` |
| `entry-points <REPO>` | Exported, handler or main symbols nothing calls. | `--limit`, `--cursor` |
| `dead-code <REPO>` | Candidates nothing references. Dynamic dispatch is invisible. | `--limit`, `--cursor` |

## Families and claims

| Command | What it does | Flags that matter |
|---|---|---|
| `family add <DIR>` | Load a pack (`rows.md`) and snapshot it to `.comparegraph/families/<name>/rows.md`; `definition_path` is workspace-relative, `definition_hash` is its sha256, `source_path` the directory it came from. Features it no longer lists become retired. Re-run it on a store imported before snapshots to create one. | |
| `family list` / `family show` | Registered families; one family by group. Each reports `definition_path`, `definition_hash`, `source_path` and `snapshot_present`. `check` reports `family_snapshots_missing`. | |
| `family propose <NAME>` | Draft `rows.draft.md` from terms the given repos share. No model. With `--from-claims <REPO> --rows <jsonl\|->` instead of `--repos`: read the standard repo's scored rows (the `claim --batch` shape; `feature` required, `repo`, `title`, `group`, `verdict`, `note`, `at` used, other fields ignored; a row without `repo` is the standard's, a row for another repo is skipped and counted in `other_repo_rows`) and draft every id the rows name that is not an active feature of family NAME. A dotted `feature` keeps its group; otherwise the id is `<group or draft>.<slug of feature>`. Rows on one id merge (their `lines`, sorted `verdicts` and `at`). Writes `rows.from-claims.draft.md` with front matter `draft: true`, every row tier `candidate`, weight 1, definition and counts-as-has starting `draft:`; it parses as a pack but is never registered, and `rows.md` is never touched. Also returns `covered` (ids already in the family) and `stored_claims` (the repo's latest claims on NAME). Nothing missing: `drafts: []`, `draft_path: null`, no file. A line that is not a row fails the whole call, naming the line, before anything is written. | `--repos a,b,c`, `--min-repos`, `--max`, `--out`; `--from-claims`, `--rows` |
| `relate` | Score each clone against each family and record the band. | `--repo`, `--family`, `--stored` |
| `map <REPO> <FAMILY>` | Candidate symbols and communities per feature. Writes nothing. Terms skip pack bookkeeping: a parenthesised note naming a row (`(pair row)`) and the words `row`, `rows`, `specific`, `specifically`, `etc`. Ranking uses graph position as well as names: a function, method or route that code calls but that no root reaches (roots: the `entry-points` symbols, counting no test caller, and the entry files; `calls` edges, up to 10 hops) scores half. Each symbol says why it ranked: `reach` (`entry`, `reached`, `unreached`, `uncalled`: nothing outside tests calls it, so it is left alone, `not_applicable`: another kind or a run with no root), `entry_hops` (hops from the nearest root, or null), `community` and `community_peers` (other name-matched candidates in that community; reported, not scored). `data.entry_points` is the number of roots; 0 means reach was off. | `--feature`, `--limit` (5) |
| `absent-check <REPO> <FAMILY> <FEATURE> [--searched <terms>] [--include-non-code]` | Is the feature absent? Also returns `data.read_set`: `{cap: 10, total, candidates[], non_code}`; nodes parsed from css, scss or html (selectors, markup) are left out of `total` and `candidates` and counted in `non_code`, unless `--include-non-code` (MCP `include_non_code`) ranks them too; a `none` is always judged on the code-only set, and naming a non-code node as read is not a stranger; the channels and `absent` still count non-code hits. The read set is the union of the symbol, path and kind channels (and, with `--searched`, the hits of that search) ranked by score (exact name 8, name token 4, path or qualified-name substring 2, kind-only or search-only 1, +1 for a community label carrying a term; `why` lists the reasons), best first, capped at 10; `--searched` terms must name the feature, as for `claim`, and a search hit makes `absent` false. Counts and up to 5 hits over four channels: symbols, paths, community labels and keywords, node kinds the feature names. `data.absent` is true only when all four are zero. A family word (a term in the term set of at least half of the family's features and of at least 4: `agents` where every row is `agents.*`) names the family, not the feature: it is dropped from all four channels and listed in `data.common` and in the note as `common=<terms>`; a hit on a remaining term refuses as before, and zero hits with a family word set aside also refuses, naming the uncounted words (record that absence with `--searched`); when every term is a family word the check refuses and records nothing (pass `--searched` with specific terms). The symbol channel counts every node whose name carries a term, whatever its kind. Reads only. `data.reason` says why `absent` has its value: `hits` (a channel found something), `family words set aside: <words>` (every channel is zero but terms were set aside, so absence is not concluded) or `absent`. | |
| `claim <REPO> <FEATURE> <VERDICT>` | Record `has`, `partial`, `none` or `unknown`. `none` without `--searched` runs the absent check: all channels empty records it as `inferred`; any hit refuses it and lists the candidates. `none --searched <terms>` must name the feature (a word of its id, title, synonyms, definition or counts-as-has text, other than a stop word or a family word; the refusal lists at most 15 accepted words) and records `derived` when the search finds nothing. When the feature has candidates (its channel hits plus the search hits, ranked as `absent-check --searched` returns them), open the top 10 and pass their qualified names, one `--read-hits <name>` per name (repeat the flag; a name may hold a comma, a space or a newline, as css selectors and quoted yaml keys do; a value that is no candidate's name is split on commas and spaces, so the older `--read-hits a,b` still works; batch rows use `hits_read: [..]`, MCP `read_hits`, one name per element): the claim is then recorded `observed` with the note `searched: <terms> → N candidates, top 10 read and rejected: <names>` (20 names, then `+k more`); when N exceeds 10 the envelope carries a `read_capped` limitation and the note ends `; N-10 lower-ranked candidates not demanded`. A `--searched` that holds every absent-check term (`data.terms`, the family words aside) and more is a superset: it is also accepted when the names read are the top 10 of the read set of those terms alone (what `absent-check` prints with no `--searched` or with `--searched "<terms>"`), and the note then adds `; judged on the read set of the terms "<terms>" (searched is a superset)`. Every refusal of a `none` (with or without `--searched`) has error code `none_refused` and carries `error.data` (also on batch rows and over MCP): `{reason, repo, family, feature, searched, terms, common, hits_read, unread, strangers, total, cap, non_code}`, where `reason` is `graph_hits`, `family_words`, `no_read_hits`, `unread` or `strangers`, `searched` is the exact text to re-claim with (without `--searched` it is the terms, space separated) and `hits_read` is every name that `none` must then name as read (empty: `searched` alone records it); re-claiming with both, unchanged, records the none. Refusal messages: `not none: K of the top 10 candidates were not read: <all unread>; run absent-check --searched "<terms>" for the list, or claim has/partial`; `--read-hits names symbols the search does not find: <names>` (a name outside the whole union, at any rank); `--read-hits` without `--searched` or on a verdict other than `none`. With no candidate at all the claim records as before and the note says nothing was read. **What a citation must be** (checked before anything is written): a cited span whose every line is blank, a comment or a docstring is refused (`<path>:<span> cites no code (line 1 comment, …)`), so a bare `path:1` on a header no longer passes; `--allow-comment` accepts it when the comment is the evidence. Comments are judged by extension (`#`, `//`, `/* */` at line start, `--`, `<!-- -->`, Python docstrings); an unknown extension refuses only blank lines. A span whose code is only import/use/package lines passes with a `citation_imports_only` limitation. `--expect <symbol|regex>` must match a line of the cited span (one `--expect` for every `--at`, or one per `--at` in order); the refusal names the lines of the file it does match, or says it matches nowhere. `--anchor 'path::regex'` (split on the first `::`) resolves to the one code line the regex matches and is stored as `path:N`; zero matches, only comment matches (named; `--allow-comment` admits them) or several code matches (listed) refuse. A has/partial needs an `--at`, an `--anchor` or `--out-of-subset`. Patterns are a regex subset matched per line (literals, `.`, `[...]`, `\d \w \s \b`, `^ $`, groups, `|`, `* + ? {n,m}`; no look-around or back-references), since the engine takes no `regex` dependency without a ruling. `--at-commit <sha>` (7-40 hex) records the upstream commit the citations were read at (`at_commit` on the claim): it must agree, as a prefix either way, with the repo's `source_commit` when set, else its git head; a repo with neither records it under an `at_commit_unverified` limitation. `--out-of-subset <path[:lines]>` qualifies a has/partial whose evidence is upstream but outside the exported tree (tests the export dropped): it is stored as `out_of_subset`, refused when that file is in the tree (cite it with `--at`), carries an `out_of_subset` limitation, and without any `--at` the claim is `inferred`. A batch re-run treats a different `at_commit` or `out_of_subset` as a different claim. **Reach** (written with every has/partial, after the citation checks): `reach: {status, path, note}`, where `status` is `reached` (with `path`, the qualified names from an entry point to the cited symbol), `unreached` or `unknown`. It is one bounded callee walk over `calls` edges (depth 10, max-nodes 2000, name-guessed edges counted, a path through one adds `reach_name_guessed`) from every symbol `entry-points` lists, to the innermost function, method or route holding a cited line. A cited symbol that is an entry point only because nothing calls it is not a start (limitation `reach_uncalled_target`); a `main`, handler-named or route symbol is. `unknown` says why in `note` and a `reach_unknown` (or `truncated`) limitation: no cited line maps to a node, the lines sit at file or class scope, the graph has no entry points, or the walk hit its depth or node bound. `unreached` carries `reach_static_only`: dynamic dispatch, registries, decorators and framework wiring are not in the graph. A batch re-run treats a different reach as a different claim. | `--author` (required), `--at path:start-end`, `--searched`, `--read-hits <qualified_name>` (repeatable; the `read_set.candidates` names), `--note`, `--family`, `--anchor 'path::regex'`, `--expect <symbol\|regex>`, `--allow-comment`, `--at-commit <sha>`, `--out-of-subset <path[:lines]>` (batch rows: `anchor: [..]`, `expect: [..]`, `allow_comment: true`, `at_commit`, `out_of_subset`), `--batch <jsonl\|->` (one JSON object per line, e.g. `{"repo":"a","feature":"x.y","verdict":"has","author":"me","at":["src/a.rs:1-9"]}`; one store open and one transaction; one envelope line per row with its `line`, printed as each row is decided, then a `{rows, ok, skipped, failed, committed}` summary; rows are durable only when that last line says `committed`; exit 1 if any row failed; a row equal to the live claim (same run, verdict, author, note and locations) is skipped, reported `skipped: true` with the existing id, and counted in `skipped`, so an interrupted batch can be re-run) |
| `claims` | Latest claim per clone and feature, with its `reach` when it has one. | `--repo`, `--family`, `--feature`, `--history` |
| `decide <REPO> <DISPOSITION>` | Record `adopt`, `reject` or `park`. Append-only. | `--why`, `--by` (both required), `--feature`, `--family`, `--batch <jsonl\|->` (rows like `{"repo":"a","disposition":"park","why":"...","by":"me"}`; output as for `claim`) |
| `decisions` | Latest decision per scope. | `--repo`, `--history` |
| `matrix <FAMILY>` | Features against every clone: verdicts, prevalence, gaps, differentiators. A clone with no stored relatedness band shows `relatedness: "not run"`, and the envelope's `limitations` says how many comparators lack one. | `--relate` (score the comparators with no band first, then build the matrix; this writes relatedness rows), `--reach reached\|unreached\|unknown` (keep only the rows with a cell whose latest claim has that reach; each row carries `reach`, parallel to `cells`, when any of its claims has one) |

## Exports and agents

| Command | What it does | Flags that matter |
|---|---|---|
| `export json` | The graph as JSON (to stdout). | `--repo`, `--out` |
| `export csv` | RFC 4180 CSV: nodes, edges, claims, decisions, one matrix per family. | `--out` (required) |
| `export vault` | An Obsidian-style markdown vault, regenerated whole. | `--out` |
| `mcp` | Serve the read verbs over MCP stdio (JSON-RPC, one object per line). | |
| `setup` | Register the MCP server with agent clients. A plan by default. | `--client`, `--scope`, `--apply`, `--force`, `--bin`, `--no-rules`, `--no-hook` |
