# CLI reference

Every command, with the flags that matter.

Global options on every command, before or after the verb: `--root <ROOT>` (the workspace, default `.`), `--pretty`, `--allow-unverified` (use an
external provider with no manifest), `--root-map FROM=TO` (repeatable: re-root the clone paths a store copied from another machine holds; `doctor` lists the
registered clones missing here under `unmapped_roots`), `--wait <SECS>` (see below). `comparegraph <verb> --help` prints every flag.

`--wait <SECS>` / `COMPAREGRAPH_WAIT`: how long a writer waits for another writer's store lock (default 30, at most 3600).
`--wait` above 3600 is refused (`invalid_arguments`); `COMPAREGRAPH_WAIT` above 3600 is clamped to 3600 with a note on stderr, and
a value that is not a whole number of seconds (`abc`, `-1`) is refused (`invalid_arguments`), never silently replaced by the
default. With `--wait 0` a held lock fails at once and the error says it did not wait. When the wait runs out the error lists
the other comparegraph processes that have the store open, from the notes each one leaves in `.comparegraph/holders/`; SQLite
does not say which of them holds the lock. Limits of those notes: a process killed with SIGKILL leaves its note behind until a
later timeout finds its pid dead and removes it; a reused pid makes a stale note look live; and a process in another PID
namespace (a container sharing the store) cannot be probed, so its note may be listed as live or removed as dead wrongly.

Opening a store written by an older binary adds the newer columns once, under a write lock, so concurrent first opens wait
for each other instead of failing. A store whose `schema_version` this binary does not know is refused before anything in it
is changed. A read-only store (the file not writable) that predates those columns is not migrated: read verbs still answer
(the missing columns read as their defaults, empty or null), and writers are refused with a message saying the store is read-only.

## Build and inspect

| Command | What it does | Flags that matter |
|---|---|---|
| `add <PATH>` | Register a clone. Read, never run. With `--replace` (and `--name <existing>`) it re-points that registered repo at `<PATH>` instead: claims and runs stay, the root flag is kept unless `--as-root` is passed too. It refuses an unknown name ("nothing to replace; drop --replace") and a path the repo already has. The envelope reports `old_path`, `new_path` and the new path's `head`, with a limitation saying the last build read the old path and to run `build` again. Licence and lane come from the clone's LICENSE file; a partial export has none, so `--licence <SPDX>` records one (the lane follows it), `--licence-from <SOURCE_CLONE>` reads it from the full source clone (refused if that clone has no recognised licence either), and `--lane take\|study` sets the lane outright (it wins over the licence's lane; any other value is refused). Explicit flags win over detection; with `--replace` they are applied to the row, and without them the row keeps its licence and lane. Repo notes: `--source-commit <SHA>` records the upstream commit an export was taken from (7 to 64 hex digits; a fresh `git init` of an export has `head: null`), shown next to `head` by `add`, `repos`, `build`, `show` and the vault; `--moved-to <REPO_OR_URL>` notes where the project's core now lives (shown by `repos` and `show`; a note, never followed); `--include <GLOB>` / `--exclude <GLOB>` (repeatable, gitignore-style: a name glob matches at any depth, `dir/**` everything under `dir`, a glob that matches a directory covers its files, an exclude wins over an include; a glob starting with `!` is refused) set the default subset `build` reads. Without a path, `add --name <existing>` with any of these (or `--licence/--lane`) amends a registered repo; `''` clears a note or a glob list. `--replace` keeps the notes except `source_commit`, which named the old checkout: it is cleared (limitation `source_commit_cleared`) unless given again. | `--name`, `--as-root`, `--replace`, `--licence`, `--licence-from`, `--lane`, `--source-commit`, `--moved-to`, `--include`, `--exclude` |
| `build <REPO>` | Parse a clone into the graph (one run). The envelope's `data` names the clone `path` it read and the `head` (short commit) it found there; `--progress` prints the same as its first stderr line. | `--provider` (default `reference`), `--providers a,b` (several engines in turn, with an agreement table), `--max-file-bytes`, `--max-files`, `--full`, `--progress` (stderr lines every 500 files and per pass; also `COMPAREGRAPH_PROGRESS=1`; stdout stays one envelope), `--include <GLOB>` / `--exclude <GLOB>` (repeatable; the file subset this run reads, replacing the repo's `add` subset when either is given; recorded on the run and returned as `data.include/exclude` with `data.source_commit`; a run read with other globs is never reused; files left out are counted in limitation `out_of_subset`; an external provider walks the clone itself, so its nodes outside the subset are dropped after it answers, limitation `subset_filtered`) |
| `check` | Verify schema, the search index, citation locations and the action log. **Read-only by default** (the store is opened read-only: no flag is written, no migration, no checkpoint), also over MCP. A repo whose clone folder is missing, or whose HEAD is not the head its latest run read, is reported in `clone_unavailable` (`reason` `missing` or `head_moved`, with `locations_not_checked`) and its locations are not read: an environment failure is never recorded as drift; when every problem is of that kind the error code is `clone_unavailable`, otherwise `check_failed`. `--mark --by <who>` (CLI only) writes `stale = 1` on the locations found stale; `--mark --recompute --by <who>` also clears `stale` where the cited lines hash as recorded again (the repair path for flags left by a check that ran while a clone was away); a flagged location whose lines match again is named in `notes` until then. `--deep` adds the per-run `store_hash` recomputation (`drifted_runs`; without it `drifted_runs` is 0 and `deep: false`). Archived repos are never read (`archived_repos`). Claims citing a run restored from a claims-only backup are reported until the repo is rebuilt. Also counts `unbuilt_claim_runs`: claims whose cited run has no row or is not a finished build; each affected repo adds a problem line (`<repo>: <n> claims cite run <id> which was never built`) and the verb exits non-zero, like any other problem. `stale_locations` counts only locations of live claims (the latest claim per repo and feature, the one `matrix` and `export` treat as current) and each is a problem; `stale_locations_superseded` counts the stale locations of superseded claims (append-only history that cannot change) and is reported in `notes`, never as a problem. | |
| `repos` | Registered repos with their latest run: `head`, `source_commit`, `moved_to`, the default `include`/`exclude`, and the `include`/`exclude` the latest run read. Archived repos are left out (limitation `archived_skipped`) unless `--archived` (only them) or `--all`, which add `archived` per row. `--no-port` keeps the repos whose code must not be ported, each with `no_port` reasons: `lane <lane>` (not `take`/`adapt`), `licence <id>` (AGPL, GPL, LGPL, SSPL, BUSL, EUPL, OSL and fair-code ids: a constant set a policy's `licences.never_copy_extra` may only extend) or `licence unread`. | `--limit` (50), `--cursor`, `--archived`, `--all`, `--no-port`, `--policy` |
| `doctor` | Report the store, every provider and each agent client's registration. | `--bin`, `--brief` (plain text for a session-start hook: nothing without a store, else one or two lines; the one output that is not an envelope) |
| `conform <PROVIDER>` | Run the golden fixtures against a provider. | `--fixtures` |

## Store safety, scope and record (lane CG-STORE)

The claims are the one part of a store that cannot be rebuilt from the clones. These verbs copy them out, keep the store
from growing, rate and soft-archive repos, and record every write in the action log. None of them migrates a store written
by an older binary: they open it without adding columns (read through temp views) and write only `meta`, `location.stale`,
`run.status` and `parse_cache`, so the binary that wrote the store keeps reading it. Every write needs `--by <who>`.
(The older verbs - `repos`, `claims`, `matrix` and the rest - still add missing columns when they open a writable store.)

| Command | What it does | Flags that matter |
|---|---|---|
| `backup --by <who>` | A consistent full copy, `VACUUM INTO <out>/comparegraph-<UTC>.db` (one snapshot; readers and writers keep going under WAL), then `PRAGMA quick_check` and the row counts of 14 tables compared with the source before and after the copy; refused (nothing kept) when they disagree. `--claims-only`: `comparegraph-claims-<UTC>.jsonl` with every row of `meta`, `repo`, `family`, `feature`, `run` (no graph), `claim`, `location`, `decision`, `relatedness` and the action log, read in one snapshot and re-read from disk before it is kept. Beside each file a `backup-manifest/1` (`<file>.manifest.json`: sha256, bytes, counts, engine, `store_digest`, `store_predates_binary`). A backup is never overwritten. `--keep n` then removes the oldest backups of the same kind in `--out` only. A broken action log does not stop a backup (limitation `action_log_not_written`). | `--out` (default `.comparegraph/backups`), `--claims-only`, `--keep` |
| `restore-store <backup>` | A plan by default. `--apply --by <who>`: the backup's sha256 must match its manifest (`backup_mismatch` otherwise, store untouched) and a full copy must pass `quick_check`; refused (`store_busy`) while another comparegraph process has the store open or another connection holds its write lock; then a pre-restore full backup into `.comparegraph/backups`, the current files moved to `comparegraph.db.replaced-<UTC>` (never deleted), and the copy put in, its counts checked. A claims-only backup goes into a fresh store with its ids; runs come back `restored` with no graph (limitation `graph_not_restored`): build each repo, then `check`. The store's action-log head is set to the file's, then the restore is logged. | `--apply`, `--by` |
| `gc --parse-cache` | Dry-run: rows and payload bytes per provider version, what would go, `bytes_after` labelled `estimated`. `--apply --by <who>`: delete the cache rows of every provider version except the running binary's (and the `n - 1` newest others with `--keep-versions n`, default 1 or the policy's `retention.parse_cache_versions`), then `VACUUM` and a WAL truncate; `bytes_after` is then the measured file size. Refused with `store_busy` while the store is held (it never waits) and with `insufficient_space` when less than 1.2 x the store is free on its volume. `--all-cache` drops every row (limitation `cache_dropped`: the next build parses every file). Never touches the graph, claims, locations, decisions, bands or runs. Every successful `build` also prunes, for the files it read, their rows of other provider versions (prune-on-build), so the cache stops growing between runs of `gc`. | `--apply`, `--by`, `--keep-versions`, `--all-cache`, `--policy` |
| `gc --stale-runs` | Runs still `running` that started more than `--older-than-hours` (default 24) ago: listed (dry-run), marked `abandoned` with `--apply --by <who>`. Nothing is marked while a `build` process has the store open (limitation `live_build`; `--apply` refuses with `store_busy`). | `--older-than-hours`, `--apply`, `--by` |
| `relevance` | Reads only. Per repo the factor counts: `evidence_claims` (live has/partial claims), `other_claims` (none/unknown, not scored), `pull_rows` (rows of the policy's `pull.file` naming the repo, through `aliases.file`), `days_since_cited` (newest live claim or the policy's `cited.file` date), `best_band` (over the families with a live claim), `ui` (`proven`/`listed`/`no` in the policy's `ui-registry/1` file), `days_since_added`; beside them `size_nodes`, `latest_run_status`, `no_graph`, licence, lane, `archived`. With a `relevance-policy/1` file (`--policy`, else `.comparegraph/policy.json`; the files it names are relative to it) a score 0..sum(weights) and a class, first match wins: `ROOT`, a live pin, `KEEP-PRIMARY`, `KEEP` (score >= `keep_min`), `KEEP-NEW` (added within `grace_days`), `REMOVE-CANDIDATE` (score < `remove_max`, no evidence claim, no pull row), `ARCHIVE`. Without one every repo is `unrated` (the engine ships no weights). Ages count to `--as-of` (default: the newest timestamp in the store, never the clock). Sorted by class, score, name; paged (`--limit` 1..=500). `data.inputs`: engine, `policy_sha256`, the sha256 of every file the policy names, each family's `definition_hash`, `store_digest`. Unknown policy keys are refused (`invalid_policy`). `--explain <repo>` prints every term. An example policy encoding the D405 primaries: `docs/examples/relevance-policy.d405.json`. | `--policy`, `--family`, `--explain`, `--class`, `--as-of`, `--limit`, `--cursor` |
| `archive <REPO> --why <text> --by <who>` | A SOFT archive. Dry-run by default (the plan, nothing written). Refused always for the workspace root (`cannot_archive_root`) and an archived repo (`already_archived`); refused (`archive_refused`, `error.data.guards`) for a policy primary, a pinned repo, a repo a decision adopts (or one of its features) and a repo with pull rows, unless `--force-with-reason "<why>"` (copied into the manifest and the log). `--apply`, under the store's write lock: `.comparegraph/archive/<repo>.claims.csv` and the `archive-manifest/1` (`<repo>.json`: remote, head, path, licence, lane, rating, runs, bands, claims count and sha256, why, by, forced) are written (temp file, fsync, rename) and re-read, then the `meta` flag `archived:<repo>` (= the manifest's sha256) and the log entry. No row of the graph, claims, locations, decisions or bands is changed. The repo then leaves `repos`, `matrix`, `relate`, `search` and `export` (listings say `archived_skipped`), `check` never reads it (its clone may be moved away), and `claim`, `decide`, `build`, `map`, `absent-check` refuse it (`repo_archived`); `claims --repo` and `decisions --repo` still answer. | `--apply`, `--policy`, `--force-with-reason` |
| `restore <MANIFEST.json or REPO> --by <who>` | The manifest must hash to the archive flag (`manifest_mismatch`); the clone folder (`--path`, else the path at archive) must exist (`clone_missing`, with the `git clone ... && git checkout <head>` line to run; the engine makes no network call) at the recorded head (`head_mismatch`, unless `--rebuild`, which then runs an ordinary `build`). `--apply` lifts the flag and logs it; the repo's rows are simply back in view. | `--apply`, `--path`, `--rebuild` |
| `governance verify` | Reads only. Re-walks `.comparegraph/actions.jsonl` (`action/1`, one line per write: `seq`, `at`, `verb`, `repo`, `by`, `why`, `forced`, `inputs` with the engine, `bytes_before/after`, `prev`, `hash` = sha256(prev + canonical entry)): every hash recomputes, `seq` is gapless, the head equals `meta.actions_head` (so a file cut short disagrees with the store), every `archived:` flag has its archive entry and a manifest that still hashes to it, no restore without an archive. Fails `check_failed` naming the first broken line; `check` counts a break as a problem, `doctor` shows `governance`, and every write verb refuses to append to a broken chain (`chain_broken`). Limit: whoever can write both the file and the store can rewrite both. | |
| `catalog` | Print the MCP tool catalog as JSON. | `--check` (compare with `docs/catalog.json`) |

## Graph queries

| Command | What it does | Flags that matter |
|---|---|---|
| `search <QUERY>` | Full-text search over symbols of each latest run. | `--repo`, `--kind`, `--limit`, `--cursor` |
| `show <REPO> <QN>` | A symbol with callers, callees, community, licence lane, and the repo's `source_commit`/`moved_to` when set. | `--detail full` |
| `communities <REPO>` | Module clusters of the latest run. | `--limit`, `--cursor` |
| `traverse <REPO> <QN>` | Nodes reachable over calls, extends, implements, with hop distance and path. | `--direction`, `--depth` (3), `--max-nodes` (200), `--kinds`, `--min-confidence` (0.5), `--limit` (50), `--cursor` |

| `entry-points <REPO>` | Exported, handler or main symbols nothing calls. | `--limit`, `--cursor` |
| `dead-code <REPO>` | Candidates nothing references. Dynamic dispatch is invisible. | `--limit`, `--cursor` |

## Families and claims

| Command | What it does | Flags that matter |
|---|---|---|
| `family add <DIR>` | Load a pack (`rows.md`) and snapshot it to `.comparegraph/families/<name>/rows.md`; `definition_path` is workspace-relative, `definition_hash` is its sha256, `source_path` the directory it came from. Features it no longer lists become retired. Re-run it on a store imported before snapshots to create one. A pack whose front matter says `draft: true` (a `family propose --from-claims` draft renamed to `rows.md`) is refused: it lists only the drafted rows, so adding it would retire every other row of the family; merge its rows into the family's `rows.md`, or pass `--accept-draft` to add it as the whole pack. | `--accept-draft` |
| `family list` / `family show` | Registered families; one family by group. Each reports `definition_path`, `definition_hash`, `source_path` and `snapshot_present`. `check` reports `family_snapshots_missing`. | |
| `family propose <NAME>` | Draft `rows.draft.md` from terms the given repos share. No model. With `--from-claims <REPO> --rows <jsonl\|->` instead of `--repos`: read the standard repo's scored rows (the `claim --batch` shape; `feature` required, `repo`, `title`, `group`, `verdict`, `note`, `at` used, other fields ignored; a row without `repo` is the standard's, a row for another repo is skipped and counted in `other_repo_rows`) and draft every id the rows name that is not an active feature of family NAME. A dotted `feature` keeps its group; otherwise the id is `<group or draft>.<slug of feature>`. Rows on one id merge (their `lines`, sorted `verdicts` and `at`). Writes `rows.from-claims.draft.md` with front matter `draft: true`, every row tier `candidate`, weight 1, definition and counts-as-has starting `draft:`; it parses as a pack but is never registered, and `rows.md` is never touched. Every free-text part of a row (title, repo name, note, citation) is made one cell (`|` becomes `/`, newlines collapse), so every draft round-trips through the pack parser; a `verdict` other than `has`, `partial`, `none`, `unknown` (case-insensitive) fails the whole call, naming the line. Merge the drafted rows into the family's `rows.md` (the envelope's `merge_note` says so): added as-is the draft would replace the family's rows, retiring every row it does not list, so `family add` refuses it without `--accept-draft`. Also returns `covered` (ids already in the family) and `stored_claims` (the repo's latest claims on NAME). Nothing missing: `drafts: []`, `draft_path: null`, no file. A line that is not a row fails the whole call, naming the line, before anything is written. | `--repos a,b,c`, `--min-repos`, `--max`, `--out`; `--from-claims`, `--rows` |
| `relate` | Score each clone against each family and record the band. | `--repo`, `--family`, `--stored` |
| `map <REPO> <FAMILY>` | Candidate symbols and communities per feature. Writes nothing. Terms skip pack bookkeeping: a parenthesised note naming a row (`(pair row)`) and the words `row`, `rows`, `specific`, `specifically`, `etc`. Ranking uses graph position as well as names: a function, method or route that code calls but that no root reaches (roots: the `entry-points` symbols, counting no test caller, and the entry files; `calls` edges, up to 10 hops) scores half. Each symbol says why it ranked: `reach` (`entry`, `reached`, `unreached`, `uncalled`: nothing outside tests calls it, so it is left alone, `not_applicable`: another kind or a run with no root), `entry_hops` (hops from the nearest root, or null), `community` and `community_peers` (other name-matched candidates in that community; reported, not scored). `data.entry_points` is the number of roots; 0 means reach was off. **Re-export shims**: a file that defines no symbol, makes no module-level call and imports files of the clone (a Python compatibility module of `from x import y` lines and `__all__`; Rust `mod`/`pub use`) is a shim of its one imported file, or of the one whose stem is its own when it imports several (several or none: not a shim; chains followed 3 deep). Its target takes the shim's ranking slot (at least the shim's score) and the shim is listed once, below it, with `shim_of: <target qualified name>`, taking no slot of `--limit`; every other symbol has `shim_of: null`. Computed from the stored `imports` edges at map time: no rebuild. TS/JS `export … from` barrels are not marked (the store holds no edge for them), and the target is the module, not the re-exported symbol (the store holds no imported names). `relate` scores the plain ranking. | `--feature`, `--limit` (5) |
| `absent-check <REPO> <FAMILY> <FEATURE> [--searched <terms>] [--include-non-code]` | Is the feature absent? Also returns `data.read_set`: `{cap: 10, total, candidates[], non_code}`; nodes parsed from css, scss or html (selectors, markup) are left out of `total` and `candidates` and counted in `non_code`, unless `--include-non-code` (MCP `include_non_code`) ranks them too; a `none` is always judged on the code-only set, and naming a non-code node as read is not a stranger; the channels and `absent` still count non-code hits. The read set is the union of the symbol, path and kind channels (and, with `--searched`, the hits of that search) ranked by score (exact name 8, name token 4, path or qualified-name substring 2, kind-only or search-only 1, +1 for a community label carrying a term; `why` lists the reasons), best first, capped at 10; `--searched` terms must name the feature, as for `claim`, and a search hit makes `absent` false. Counts and up to 5 hits over four channels: symbols, paths, community labels and keywords, node kinds the feature names. `data.absent` is true only when all four are zero. A family word (a term in the term set of at least half of the family's features and of at least 4: `agents` where every row is `agents.*`) names the family, not the feature: it is dropped from all four channels and listed in `data.common` and in the note as `common=<terms>`; a hit on a remaining term refuses as before, and zero hits with a family word set aside also refuses, naming the uncounted words (record that absence with `--searched`); when every term is a family word the check refuses and records nothing (pass `--searched` with specific terms). The symbol channel counts every node whose name carries a term, whatever its kind. Reads only. `data.reason` says why `absent` has its value: `hits` (a channel found something), `family words set aside: <words>` (every channel is zero but terms were set aside, so absence is not concluded) or `absent`. | |
| `claim <REPO> <FEATURE> <VERDICT>` | Record `has`, `partial`, `none` or `unknown`. `none` without `--searched` runs the absent check: all channels empty records it as `inferred`; any hit refuses it and lists the candidates. `none --searched <terms>` must name the feature (a word of its id, title, synonyms, definition or counts-as-has text, other than a stop word or a family word; the refusal lists at most 15 accepted words) and records `derived` when the search finds nothing. When the feature has candidates (its channel hits plus the search hits, ranked as `absent-check --searched` returns them), open the top 10 and pass their qualified names, one `--read-hits <name>` per name (repeat the flag; a name may hold a comma, a space or a newline, as css selectors and quoted yaml keys do; a value that is no candidate's name is split on commas and spaces, so the older `--read-hits a,b` still works; batch rows use `hits_read: [..]`, MCP `read_hits`, one name per element): the claim is then recorded `observed` with the note `searched: <terms> → N candidates, top 10 read and rejected: <names>` (20 names, then `+k more`); when N exceeds 10 the envelope carries a `read_capped` limitation and the note ends `; N-10 lower-ranked candidates not demanded`. A `--searched` that holds every absent-check term (`data.terms`, the family words aside) and more is a superset: it is also accepted when the names read are the top 10 of the read set of those terms alone (what `absent-check` prints with no `--searched` or with `--searched "<terms>"`), and the note then adds `; judged on the read set of the terms "<terms>" (searched is a superset)`. Every refusal of a `none` (with or without `--searched`) has error code `none_refused` and carries `error.data` (also on batch rows and over MCP): `{reason, repo, family, feature, searched, terms, common, hits_read, unread, strangers, total, cap, non_code}`, where `reason` is `graph_hits`, `family_words`, `no_read_hits`, `unread` or `strangers`, `searched` is the exact text to re-claim with (without `--searched` it is the terms, space separated) and `hits_read` is every name that `none` must then name as read (empty: `searched` alone records it); re-claiming with both, unchanged, records the none. Refusal messages: `not none: K of the top 10 candidates were not read: <all unread>; run absent-check --searched "<terms>" for the list, or claim has/partial`; `--read-hits names symbols the search does not find: <names>` (a name outside the whole union, at any rank); `--read-hits` without `--searched` or on a verdict other than `none`. With no candidate at all the claim records as before and the note says nothing was read. **What a citation must be** (checked before anything is written): a cited span whose every line is blank, a comment or a docstring is refused (`<path>:<span> cites no code (line 1 comment, …)`), so a bare `path:1` on a header no longer passes; `--allow-comment` accepts it when the comment is the evidence. Comments are judged by extension (`#`, `//`, `/* */` at line start, `--`, `<!-- -->`, Python docstrings, including a one-quote string literal on the line after a one-line `def`/`class` header); every non-blank line of a prose file (`.md`, `.markdown`, `.txt`, `.text`, `.rst`) is `prose` and refused the same way (`--allow-comment` admits it); any other unknown extension (`.ipynb` too) refuses only blank lines. An `--at` range must have 1 <= start <= end (a reversed `x.py:9-3` is refused). A span whose code is only import/use/package lines passes with a `citation_imports_only` limitation. `--expect <symbol|regex>` must match a line of the cited span (one `--expect` for every `--at`, or one per `--at` in order); the refusal names the lines of the file it does match, or says it matches nowhere. `--anchor 'path::regex'` (split on the first `::`) resolves to the one code line the regex matches and is stored as `path:N`; zero matches, only comment matches (named; `--allow-comment` admits them) or several code matches (listed) refuse. A has/partial needs an `--at`, an `--anchor` or `--out-of-subset`. Patterns are Rust `regex` syntax matched per line (no look-around or back-references; inline flags such as `(?i)` work). The `regex` crate matches in linear time without recursion, so a long (minified) line never overflows the stack; a pattern whose compiled program passes 1 MiB (`(a{1000}){1000}`) is refused when parsed. `--at-commit <sha>` (7-40 hex) records the upstream commit the citations were read at (`at_commit` on the claim): it must agree, as a prefix either way, with the repo's `source_commit` when set, else the git head the latest finished build read (recorded on the run, also when a build reuses the previous run), else the head `add` saw (a run built before the head was recorded); a repo with none of them records it under an `at_commit_unverified` limitation. `--out-of-subset <path[:lines]>` qualifies a has/partial whose evidence is upstream but outside the exported tree (tests the export dropped): it is stored as `out_of_subset`, refused when that file or directory is in the tree (cite it with `--at`), when any part of the path is a symlink in the clone (dangling, or pointing out of it: the check never follows a link nor touches a path outside the clone), and when its range is reversed, carries an `out_of_subset` limitation, and without any `--at` the claim is `inferred`. A batch re-run treats a different `at_commit` or `out_of_subset` as a different claim. **Reach** (written with every has/partial, after the citation checks): `reach: {status, path, note}`, where `status` is `reached` (with `path`, the qualified names from an entry point to the cited symbol), `unreached` or `unknown`. It is one bounded callee walk over `calls` edges (depth 10, max-nodes 2000, name-guessed edges counted, a path through one adds `reach_name_guessed`) from every symbol `entry-points` lists, to the innermost function, method or route holding a cited line. A cited symbol that is an entry point only because nothing calls it is not a start (limitation `reach_uncalled_target`); a `main`, handler-named or route symbol is. `unknown` says why in `note` and a `reach_unknown` (or `truncated`) limitation: no cited line maps to a node, the lines sit at file or class scope, the graph has no entry points, or the walk hit its depth or node bound. `unreached` carries `reach_static_only`: dynamic dispatch, registries, decorators and framework wiring are not in the graph. A batch re-run treats a different reach as a different claim. A batch builds the run's reach state (the entry points, the walk's caches and the walk from every entry point) once and shares it across its rows, so reach costs one walk per run, not one per row; a single `claim` builds it once. `--no-reach` (batch rows: `no_reach: true`) skips the walk and records no reach, as a `none` or `unknown` does.
